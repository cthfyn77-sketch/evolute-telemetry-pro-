# Evolute Telemetry Pro

Отдельное Android-приложение для локального мониторинга Evolute i-JOY. Package ID: `com.evolute.telemetrypro`.

## Уже добавлено в проект
- Отдельный Compose-интерфейс в тёмном Pro-стиле.
- Получение телеметрии через официальный EVACONNECT MCP STDIO server, запущенный локально через Termux bridge.
- Хранение ключа локального bridge в AES-GCM с ключом Android Keystore.
- Отдельная SQLite-база локальных снимков телеметрии.
- Foreground-сервис, автоматический запуск после успешной авторизации и повторный запуск при следующем открытии приложения.
- Опрос телеметрии раз в 30 секунд.
- Получение SOC, одометра, штатного запаса хода, статуса online/ready и выбранных реальных датчиков.
- Расчёт запаса хода по SOC, интерполированному на целых километровых отметках, с окном 10 км. Во время зарядки окно сбрасывается; до накопления валидной истории используется OEM range.
- Unit-тесты расчётного алгоритма.
- GitHub Actions: тесты и сборка debug APK как artifact.

## Безопасность и ограничения
- Исходный APK и старые репозитории не изменяются.
- Package ID, база и Keystore alias нового приложения отдельные.
- Только чтение API. Команды автомобилю не отправляются.
- Ключи и учётные данные не включаются в логи, CSV или исходники.
- Данные остаются на устройстве.
- Android может ограничивать фоновую работу. Сервис использует постоянное уведомление и START_STICKY; если ОС или пользователь остановили приложение, повторный запуск гарантируется при следующем открытии приложения. Автоматический старт foreground dataSync сервиса из BOOT_COMPLETED не используется из-за ограничений новых версий Android.

## EVACONNECT MCP bridge

Для получения телеметрии через настоящий `evaconnect-mcp` используется его STDIO MCP transport. Android-приложение не может напрямую читать STDIO другого процесса, поэтому предусмотрен локальный адаптер `tools/evaconnect_mcp_bridge.py`.

1. Установите EVACONNECT Python-клиент и MCP-зависимости в одном окружении Python 3.12+: `pip install "mcp>=1.2" "psycopg[binary]>=3.2"`.
2. Выполните штатный вход EVACONNECT через `login.py`. Учётные данные должны находиться в `~/.config/evolute/credentials.json`.
3. Запустите bridge из того же виртуального окружения: `python tools/evaconnect_mcp_bridge.py`.
4. Bridge слушает только `127.0.0.1:8765`. Секрет создаётся автоматически в `~/.config/evolute/bridge-token` с правами файла 0600. Не публикуйте его и не меняйте адрес прослушивания на 0.0.0.0.
5. В отдельной сессии Termux выполните `python tools/check_evaconnect_mcp_bridge.py`. Скрипт проверит `/health`, ключ и структуру ответа MCP; он не выводит ключ, полный ответ или GPS-данные. Для ручной проверки доступны `GET http://127.0.0.1:8765/health` и `GET /v1/status` с заголовком `X-Bridge-Token`.

Адаптер вызывает только MCP-инструмент `evolute_status`; команды управления автомобилем не экспортируются. GPS и другие персональные координаты не запрашиваются (`include_pii=false` по умолчанию). MCP-сервер запускается отдельным процессом на каждый запрос; соблюдайте интервал опроса не чаще одного раза в 5 секунд.

Android-приложение обращается к bridge по `127.0.0.1:8765`, а ключ вводится в стартовом экране и сохраняется в Android Keystore. Коллектор уже переведён на MCP bridge; прямой EVACONNECT API для получения телеметрии больше не используется. При отсутствии MCP readiness-флага приложение сохраняет его как неизвестный статус, а не подменяет значением «не готов».

## Сборка
Workflow `.github/workflows/android.yml` всегда выполняет `gradle testDebugUnitTest`. Сборка и публикация debug APK отключены по умолчанию и запускаются только отдельным ручным запуском workflow с `build_apk=true`.
